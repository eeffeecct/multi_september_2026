# 1. Первая часть

**"Выбрать производительный пул(ы) для производительного чтения файлов"**

Подробное объяснение лежит тут: `disk.yandex.ru/i/HVYVoL88OvtuYw`
*(в начале ссылки поставьте `https` и уберите пробелы — сделано так, чтобы боты не скопировали публичную ссылку)*

1. Используя файл `FileGenerator`, сгенерьте 10к файлов (они появятся в папке `output`).
2. Напишите производительный `AtomicLongSum`, который с помощью выбора правильного пула даст максимально производительное решение.
   Смысл программы — параллельно прочитать файлы внутри папки и сложить все числа на каждой из строчек, разделенных пробелом.
3. Третья часть опциональна, но крайне рекомендуема — посмотрите, как ведет себя ваша программа внутри контейнера. Для этого:
    - сначала скомпилируйте код (запустите `script.bat`);
    - затем запустите `script.bat`.

   На первом запуске внутри контейнера будет 4 процессора. Затем опустите это число до 2, 1 и 0.5 (`--cpus="4"`) и оцените, насколько падает производительность.

# 2. Вторая часть

**"Напишите свой пул потоков со следующими требованиями"**

1. Должен иметь возможность указания размера внутренней очереди.
2. Должен иметь функцию `shutdown`, чтобы закрываться, когда его попросят прекратить работу.
3. Должен иметь возможность работать на потоках-демонах, чтобы в случае необходимости закрывался сразу.
4. Должен иметь возможность декларирования backpressure-поведения (когда очередь переполнена). Сделайте два варианта:
    - **Drop** — тихий отказ;
    - **Reject** — отказ с выбросом исключения.
5. Должен иметь возможность интерцепции, когда таск взят в работу и когда работа с ним закончена.
